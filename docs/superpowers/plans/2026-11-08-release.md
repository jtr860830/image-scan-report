# Release Implementation Plan (plan 4 of 4)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Version 1 can be pulled as a container image, run as a Kubernetes CronJob or a Podman command, upload its report over HTTP, and ship with correct third-party notices — with the renderer's memory footprint measured and reduced first so the container limits in the docs are honest.

**Architecture:** The Typst templates are tuned by measurement (four experiments, each kept only if it saves ≥ 5 % time or memory at 50 000 findings without changing the golden text). An `HttpSink` reuses `source::http::HttpClient` with one new byte-sending method and implements `raw` and `multipart` uploads. A two-stage Containerfile builds the static-asset-embedding binary into a distroless non-root image; `deploy/` holds the CronJob/Job/Podman examples; `cargo about` generates the notices; a tag-triggered workflow publishes binaries and the image to GHCR. The product name stays in its three places, so the final rename is a documented three-line change plus the image name.

**Tech Stack:** existing crate (ureq 3, serde, typst 0.15); `cargo-about` 0.9 (CI only; latest 0.9.3 on 2026-11-08); Docker/Podman multi-stage build on `rust:1.99-trixie` → `gcr.io/distroless/cc-debian13:nonroot` (both Debian 13, so the builder’s glibc matches the runtime’s); GitHub Actions (`docker/build-push-action`, GHCR).

**Spec:** `docs/superpowers/specs/2026-11-07-product-redesign-design.md` §12 (outputs), §13 (configuration and operation: CLI, exit codes, container, Kubernetes), §14 (repository layout: `deploy/`), §15 (sinks and end-to-end tests), §17 "Release shape", §18 (name). Read first: `docs/superpowers/plans/2026-11-08-rendering-deferred.md` (performance follow-ups, T1 notices items, T3 string fixes) and `docs/superpowers/plans/2026-11-08-api-sources-deferred.md` (tags rendering, `check` state counts, `--version`).

## Global Constraints

- Everything plans 1–3 established still binds: the product name appears only in `Cargo.toml [package] name`, the binary name and `PRODUCT_NAME` (`src/main.rs`); the library is `image_scan_report`; the user agent is `image-scan-report/<version>`; English code/comments/docs; Apache-2.0; secrets only from the environment and never in logs or error messages; Codex builds run cargo `--offline` after the controller fetches new crates.
- Rendering settings measured in plan 2 are preserved (PDF tagging off, no `raw`, one rayon thread, no package resolver, deterministic output). A performance experiment is **kept only if** the 50 000-finding release run improves time or peak RSS by ≥ 5 % **and** `cargo test --test golden` still passes unchanged **and** the PNG previews of the inventory and image pages show no visual difference the controller can see.
- Outputs (spec §12): `filesystem` unchanged; `http` has `url`, `method` PUT (default) or POST only, `headers` (values may use `${NAME}`, resolved at config load — already implemented), `mode: raw | multipart` (default raw), `ca_file`, `insecure_skip_verify` (same semantics and warning as the sources), `timeout_secs` (default 30), 3 attempts with 1 s / 2 s backoff on connection errors and 5xx (the client's existing rule); 4xx fail immediately. `raw` sends the bytes with `Content-Type: <artifact media type>` and `Content-Disposition: attachment; filename="<file name>"`; `multipart` sends `multipart/form-data` with one part named `file` carrying the same filename and content type. `json: true` sends the JSON artifact to every sink as well. A sink's `describe()` prints method + URL only, never headers.
- Exit codes unchanged: 0 when at least one sink stored every artifact (failed sinks are printed as `failed sink: …`), 5 when every sink failed; 2/3/4 as before.
- CLI (spec §13): `run`, `check`, `version`, plus `--version`/`-V` on the top-level command; `--config` defaults to `/etc/report/config.yaml`.
- Container (spec §13): non-root (`nonroot` user, uid 65532), reads config and CA from mounts, default command `run --config /etc/report/config.yaml`, writes to `/output`; image labels `org.opencontainers.image.{source,version,licenses,description}`; published to GHCR as `ghcr.io/jtr860830/<package name>:<semver>` and `:latest`; `podman save`/`load` documented as the air-gap path. No network access at run time other than the configured scanner and sink URLs.
- Kubernetes (spec §13): `deploy/k8s/` with ConfigMap, Secret, PVC, CronJob and a one-off Job; resource request **1 CPU / 1 GiB**, limit set from the Task 1 measurement (`ceil(peak RSS at 20 000 findings, GiB) + 1 GiB`), with the measured MB-per-1 000-findings rule of thumb in the docs replacing the spec's provisional 40 MB figure.
- Notices: `THIRD_PARTY_NOTICES.md` is generated by `cargo about` from `about.toml` + `about.hbs` (crates) and a hand-maintained fonts section; it must not contain the product name (white-label); CI fails when the committed file is stale.

## Review Focus

1. The HTTP sink target rejects the upload (401 or 5xx after three attempts) while the filesystem sink succeeded — exit 0, the report is on disk, stderr says `failed sink: HTTP PUT <url>: …` without any header value (Task 2: `one_failed_sink_keeps_exit_zero_and_hides_headers`).
2. A header value `${UPLOAD_TOKEN}` whose variable is unset — exit 2 before anything is fetched or rendered, message names the variable (Task 2: `unset_header_variable_is_config_error` — already partly covered by `config` tests; the pipeline-level ordering is the new assertion).
3. A multipart upload of a multi-megabyte PDF — the receiver sees exactly one part named `file`, the right filename and content type, CRLF line endings and a closing boundary (Task 2: `multipart_body_is_well_formed`).
4. The container started with a read-only root filesystem and a `/output` volume as uid 65532 — `check` and `run` both succeed and the PDF appears in the volume (Task 4 CI smoke test `container-smoke`).
5. `judex run` with no `--config` in the container — uses `/etc/report/config.yaml` and, when it is absent, exits 2 with "cannot read /etc/report/config.yaml" (Task 3: `default_config_path_is_etc_report`).

impl HttpClient {

    pub fn send_bytes(&self, method: &str /* "PUT" | "POST" */, url: &str, headers: &[(&str, &str)], content_type: &str, body: &[u8]) -> Result<Response<Vec<u8>>, HttpError>;
}
pub fn client_from_tls(ca_file: Option<&Path>, insecure_skip_verify: bool, timeout: Duration) -> Result<HttpClient, HttpError>;
// src/sink/http.rs
pub struct HttpSink { url: String, method: String, headers: Vec<(String, String)>, mode: HttpMode, client: HttpClient }
pub fn multipart_body(boundary: &str, field: &str, file_name: &str, content_type: &str, bytes: &[u8]) -> Vec<u8>;   // RFC 7578: CRLF, `--boundary`, Content-Disposition: form-data; name="file"; filename="…", Content-Type, blank line, bytes, CRLF, `--boundary--` CRLF

impl ReportSink for HttpSink { fn describe(&self) -> String /* "HTTP PUT https://…" */; fn store(&self, artifact: &Artifact) -> Result<(), SinkError> }
